# Лабораторна робота №7 — TextAnalyzer (варіант 14)

Статична бібліотека C++20 поєднує збережену функціональність PolynomialSolver
із «ЛР 4» та клас `TextAnalyzer` для варіанта 14. У джерелах ЛР 4 був
PolynomialSolver (варіант 6), а не попередня реалізація TextAnalyzer: його
публічний C API та алгоритми перенесені до цієї роботи, а TextAnalyzer
реалізовано відповідно до призначеного варіанта. На відміну від початкової
DLL, у ЛР 7 обидві частини збираються в одну статичну бібліотеку. Файли цієї
роботи розміщені лише в папці «ЛР 7».

## Збирання та запуск

Потрібні Visual Studio з підтримкою C++20, CMake та vcpkg. З кореня цієї
папки у PowerShell:

```powershell
cmake -S . -B build `
  -DCMAKE_TOOLCHAIN_FILE="$env:VCPKG_ROOT\scripts\buildsystems\vcpkg.cmake" `
  -DVCPKG_TARGET_TRIPLET=x64-windows
cmake --build build --config Debug
ctest --test-dir build -C Debug --output-on-failure
```

`vcpkg.json` оголошує залежність Google Test; CMake у manifest mode встановлює
її для вибраного triplet. `text_analyzer` — статична бібліотека з TextAnalyzer і PolynomialSolver.
`text_analyzer_demo` — демонстраційна програма, `text_analyzer_tests` —
окремий модульний тестовий executable, `bad_exception_demo` — приклад
некоректних типів винятків.

Демонстраційна програма за замовчуванням намагається відкрити відсутній файл,
щоб показати обробку помилки й збереження попередньої статистики. Щоб
проаналізувати файл:

```powershell
.\build\Debug\text_analyzer_demo.exe .\document.txt
.\build\Debug\bad_exception_demo.exe
```

## Інваріанти та поведінка API

- `word_count_` дорівнює сумі частот у приватній мапі `frequencies_`.
- Публічний API не надає змоги змінити мапу або лічильник окремо.
- Копіювання зберігає обидві частини інваріанта; переміщення залишає
  початковий об'єкт коректно порожнім.
- Порожній текст є коректним вхідним значенням; `topWords` на ньому повідомляє
  про відсутність слів.
- Текст має бути коректним UTF-8. Латинські та кириличні великі літери
  нормалізуються до нижнього регістру; сортування нічиїх у `topWords`
  виконується лексикографічно за нормалізованим словом.
- Параметр пошуку має містити рівно одне слово; невідоме, але коректне слово
  має частоту 0. `topWords` приймає лише додатне `N` і повертає не більше
  наявної кількості унікальних слів.
- `loadFile` розрізняє відсутній шлях і помилку читання (у тому числі шлях до
  каталогу). Помилки доступу, некоректний UTF-8 і помилки виділення пам'яті
  не змінюють раніше збережену статистику.

## Ієрархія винятків

`AnalyzerError : std::runtime_error` є базовим користувацьким винятком.
Спеціалізовані `FileNotFoundError`, `FileReadError` і `EmptyWordSetError`
надають зрозумілу причину; повідомлення файлових винятків містять шлях та
додаткові відомості. `std::invalid_argument` використовується для
некоректного UTF-8, непозитивного `N` і некоректного пошукового параметра,
`std::overflow_error` — для переповнення лічильників.
Збережений C API PolynomialSolver не пропускає C++-винятки через межу ABI:
він перетворює їх на `PolynomialStatus`; тести також перевіряють похідну,
обчислення коренів і обробку малих вихідних буферів.

Демонстраційний ланцюжок `main` → `loadDocument` → `loadWithDiagnostics` →
`readAtLeaf` → `TextAnalyzer::loadFile` передає файловий виняток з нижнього
рівня. `loadWithDiagnostics` перехоплює його за `const&`, додає діагностику й
повторно генерує тим самим `throw;`. Обробники демонстрації розміщено від
спеціалізованих до загального `std::exception`.

## Гарантії виняткової безпеки та RAII

- `analyzeText` і `loadFile`: **strong guarantee**. Спочатку текст повністю
  розбирається у локальні тимчасові дані; лише після успіху карта та загальний
  лічильник фіксуються операціями `swap`. Будь-яка помилка до фіксації
  залишає попередній стан незмінним.
- Копіювальне присвоєння має **strong guarantee** через тимчасову копію та
  `swap`; переміщувальні конструктор і присвоєння мають гарантію **nothrow**.
- `wordCount` і `uniqueWordCount`: **nothrow** і позначені `noexcept`; вони не
  змінюють стан. `frequencyOf` і `topWords` стану не змінюють, але можуть
  кидати винятки через валідацію або виділення пам'яті.
- `ScopeLogger` керується автоматично за RAII. Його деструктор має `noexcept`
  та не допускає виходу винятку під час розкручування стека. Інші ресурси
  (файли та тимчасові контейнери) належать RAII-об'єктам стандартної
  бібліотеки.

### Очікуваний порядок логів ScopeLogger

Для запуску без аргументів очікується відсутній файл
`__text_analyzer_demo_missing_file__.txt`. Шляхові дані у повідомленні
винятку скорочено:

```text
ScopeLogger: створено main
Початкова кількість слів: 5
ScopeLogger: створено loadDocument
ScopeLogger: створено loadWithDiagnostics
ScopeLogger: створено readAtLeaf
ScopeLogger: знищено readAtLeaf
Діагностика проміжного рівня: Text file does not exist: ...
ScopeLogger: знищено loadWithDiagnostics
ScopeLogger: знищено loadDocument
Файл відсутній: Text file does not exist: ...
Після операції кількість слів: 5
ScopeLogger: знищено main
```

Деструктор `readAtLeaf` запускається першим під час розкручування стека; потім
проміжна функція виводить діагностику, повторно генерує виняток і руйнуються
її локальні об'єкти та об'єкти рівня вище. Усі демонстраційні повідомлення
виводяться в один потік, тому їх фактичний порядок можна напряму порівняти з
очікуваним.

## Невдалий тип винятку

`bad_exception_demo` генерує `int` і `std::string`. Обробник
`catch (const std::exception&)` їх не перехоплює; керування доходить до
`catch (...)`. Для бібліотечного коду слід використовувати стандартні типи
винятків для типових умов (наприклад, `std::invalid_argument`) і
предметно-орієнтовані класи, похідні від `std::exception`, для діагностичних
помилок. Примітивні типи та рядки не мають узгодженої ієрархії і ускладнюють
обробку.

## Модульні тести й результати

Google Test перевіряє успішний аналіз тексту й файла, частоти та порядок
`topWords`, граничні значення, кожну категорію помилок і незмінність
статистики після невдалої операції. Тести з `EXPECT_NEAR` перевіряють
обчислення поліномів із числами з плаваючою комою.

Негативний самоконтроль виконано: тимчасова помилка (подвоєння інкремента
загальної кількості слів) спричинила падіння
`CountsWordsAndNormalizesLatinAndUkrainianCase` з фактичним значенням 8 замість
4. Помилку відновлено; після цього повторно пройдено всі 15 тестів.
